# Work Charter

Keep the agreement smaller than the work it protects. Carry the authorized outcome
through implementation, verification, necessary review, correction and delivery.

<a id="lightweight-entry-and-material-changes"></a>
## Start With The Outcome

Reuse the existing goal, scope, acceptance and authority. Honor discussion-only,
read-only and user-fixed boundaries. For delivery, identify the final user result,
earliest useful complete result and acceptance floor in the intended environment.

The delivery owner chooses a sufficient route, reuses capabilities, implements,
verifies and repairs. Compare remaining cost including delay, user attention,
coordination and maintenance. Reconsider a failed premise before further investment.
Continue authorized work to acceptance; report the result, gap and next action.

## Least Sufficient Work Arrangement

| Arrangement | Responsibility |
| --- | --- |
| Direct, the ordinary default | D owns exploration, planning, implementation, checks, repair and delivery. |
| Phased, when selected | O owns goals, priorities, cross-workstream tradeoffs and agreed outcome acceptance; workstreams default to Direct. |
| Team, when selected | P owns the contract and acceptance; E implements and verifies; independent R reviews where required. |

Use the approved arrangement and its existing decision and writer owners.
Use Team when a separate owner must hold the workstream contract and acceptance;
otherwise keep the workstream Direct.
New formal agreements may use arrangement-v2 in their existing carrier;
ordinary Direct work uses the current task or project owner.

## Shared Protections And Method Autonomy

Approval binds outcome, scope, acceptance, permitted effects and user-fixed
methods. The delivery owner chooses ordinary methods and in-scope repair.
Resolve reserved or uncovered effects before the dependent action and continue
independent authorized work. Follow actual instruction priority and host permissions.

- Keep secrets and credentials within authorized channels and out of output,
  logs and Git.
- Keep one accountable writer per overlapping write surface. Transfer ownership
  before another actor writes, and preserve unrelated changes. Approved parallel
  work uses isolated candidate surfaces and one integration owner where they meet.
- Before an action could duplicate an uncertain non-repeatable effect,
  reconcile the original effect.
- Carry explicit stops and actual consumed limits with the same work subject
  across task, attempt, branch and version changes.

Obtain an explicit answer to a missing user decision. Silence, timeouts, default
options, context compaction and tool failure do not constitute approval.

Apply [Review Input](references/coordination-and-recovery.md#review-input-at-any-level)
to choose independent review. The author repairs; R inspects a stable target
read-only. Report source checks, deployed state and accepted outcomes separately.

Obtain user confirmation of concrete new, materially changed or retired standing
project rules under [Project Rule Decisions](references/coordination-and-recovery.md#project-rule-decisions).
Maintain ordinary documents and faithfully record confirmed rules within existing
authority. Keep proposed rules outside active instructions.
